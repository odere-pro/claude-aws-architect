# Changelog

All notable changes to `claude-aws-architect` are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

One entry is added per merged PR. The plugin starts at `v0.1.0` — no `v0.0.x` versions exist. Until v0.1.0 is tagged (per [PR-PLAN.md](./docs/plan/PR-PLAN.md) PR 31, which gates the tag on the release-dogfood gate), all PR entries accumulate under `## [Unreleased]` and are promoted to `## [0.1.0]` at tag time.

### Added

- **PR 0**: Planning import. `docs/plan/SPEC-v4.md` (full v4 declarative spec, sections 0–18), `docs/plan/PR-PLAN.md` (33-PR execution roadmap with dependencies and parallel-safe flags), `docs/plan/PR-CONVENTIONS.md` (branch naming, commit format, merge strategy).
- **PR 1**: Plugin scaffold. `.claude-plugin/plugin.json` (manifest with `name`, `version`, `engines.claude-code`), `.mcp.json` (6 AWS MCP servers with short identifiers, pinned versions, and `timeoutMs`), `README.md` (with Trademark notice), `SPEC.md`, `LICENSE` (MIT), `SECURITY.md` (vulnerability disclosure), `SUPPORT.md` (community-driven posture), `CHANGELOG.md` (this file).
- **PR 2**: Deterministic gates 1–18 in CI. 16 gate scripts under `tests/gates/` (gates 1 and 13 deferred until PR 27 ships init/doctor); `tests/gates/lib/common.sh` shared helpers (bash 3.2 compatible — uses `read_into` instead of `mapfile`); cached MCP tool lists under `tests/gates/cache/tools-<key>.txt` (seeded from upstream awslabs READMEs); `tests/gates/cache/known-overshoots.txt` documenting 12 upstream-controlled tool names that exceed the 64-char tool-name budget (WARN-only, with citation of which agent/skill depends on each); `.markdownlint.jsonc` config with rationale for every disabled rule; `.github/workflows/gates.yml` with three jobs (Linux bash 5+, macOS system bash 3.2, macOS brew bash 5+) — explicit `/bin/bash` invocation on macOS asserts the "tested on macOS bash 3.2" claim. Markdown auto-formatted with prettier 3.6.2.
- **PR 3**: Transcript-replay harness skeleton. `tests/run-transcripts.sh` (validate-only mode at v0.1.0; execute and update-snapshots modes stubbed pending PR 18); `tests/transcripts/README.md` (fixture format reference); first fixture `tests/transcripts/vibe-shallow/` (validates the verb-of-inquiry → shallow depth rule — no fan-out, no artefacts written) with `prompt.txt`, `expected-tools.jsonl`, and `expected-artefacts.txt`. New CI job `transcript-validate` wires the harness into `.github/workflows/gates.yml`. Makes gate 19 (skeleton) achievable.
- **PR 4**: Workflow skill `aws-mcp-routing`. `skills/aws-mcp-routing/SKILL.md` (canonical workflow-skill form: `**WORKFLOW SKILL** —` description, version, all five mandatory body sections including Gotchas); sibling `trigger-keywords.txt` (24 keywords, gate-16 input); three references — `server-roster.md` (the 6-server table + per-server tool catalogue), `selection-rules.md` (intent-to-server mapping + tool-selection priorities + pre/post-call obligations), `degraded-modes.md` (per-server fallback markers + lifecycle through merge contract + retry policy: none at v0.1.0). First skill ever; gates 5/10/16/17 transition from no-op PASS to enforcing PASS.
- **PR 5**: Workflow skill `aws-spec-grounding`. `skills/aws-spec-grounding/SKILL.md` (canonical workflow-skill form, all five mandatory body sections); sibling `trigger-keywords.txt` (25 keywords); three references — `cite-format.md` (`<server>:<short-key>` citation format, frontmatter vs inline placement, validation rules), `grounded-by-rules.md` (per-artefact minimums for requirements/design/tasks/contracts/ADRs, what counts as a rationale, detection algorithm, surfacing violations), `opinion-vs-fact.md` (boundary tests, examples, edge cases, resolution algorithm). Enforces that every factual AWS claim carries ≥1 citation and every design opinion carries a rationale.
- **PR 6**: Workflow skill `aws-grounding-cache`. `skills/aws-grounding-cache/SKILL.md` (canonical workflow-skill form, all five mandatory body sections); sibling `trigger-keywords.txt` (27 keywords); four references — `ledger-schema.md` (top-level structure, entry schema with `server`/`tool`/`query`/`retrieved`/`result_summary`/`ttl-class`/`short_key_ext`, conflict-resolution log, validation rules), `ttl-policy.md` (per-class windows: pricing/quota 30d, api-shape/region 90d, immutable indefinite; read-side behaviour, degraded-MCP interaction, write-side timestamp discipline), `collision-policy.md` (canonicalisation algorithm, SHA-1 short-key derivation with real verifiable example values, 8→12-hex extension on collision, lookup fallback algorithm with mandatory query-equality check at every step), `redaction-policy.md` (8-pattern catalogue with application order, negative cases, write-abort-on-failure semantics); plus `assets/grounding-ledger.json.tmpl` starter file. Enables the `<server>:<short-key>` citations consumed by `aws-spec-grounding`.

- **PR 7**: Workflow skill `aws-component-contract`. `skills/aws-component-contract/SKILL.md` (canonical workflow-skill form, all five mandatory body sections); sibling `trigger-keywords.txt` (30 keywords); two references — `contract-schema.md` (file-path rule, frontmatter keys, closed `kind` vocabulary of 21 AWS resource kinds, seven canonical body sections, status-transition table, validation rules summary), `observability-triple.md` (why three signals, what counts as a concrete metric/log/trace, what does NOT count, why lint refuses to auto-fill, interaction with the `cw` MCP server); plus `assets/contract.md.tmpl` starter file with all required frontmatter keys and seven body sections in canonical order.

- **PR 8**: Workflow skill `aws-layered-diagram`. `skills/aws-layered-diagram/SKILL.md` (canonical workflow-skill form, all five mandatory body sections); sibling `trigger-keywords.txt` (26 keywords); two references — `layer-taxonomy.md` (six required tags `c4-l1`/`c4-l2`/`c4-l3-<container>`/`seq-system`/`seq-component`/`seq-error`, tag-name rules including bare-`c4-l3` rejection, per-layer content rules, top-level node rule, orphan-node rule, cross-layer consistency boundary), `c4-and-sequence.md` (C4 model recap with audience/granularity/intent for each level, what belongs and what does NOT in L1/L2/L3, sequence-layer participants/story/length guidance, notation conventions); plus `assets/diagrams.d2.tmpl` starter file with all six required layer blocks pre-populated using d2 default syntax.
